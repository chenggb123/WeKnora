# 部署与运维说明（Milvus + MinerU 4.0）

本文记录一套已验证可用的部署形态：**WeKnora v0.8.0 + Milvus 向量库 + MinerU 4.0.4（GPU 加速解析）**，
运行环境为 Windows + Docker Desktop（WSL2）+ NVIDIA GPU。适用于「自建 GPU 服务器 + 内部使用」的场景。

## 1. 部署拓扑

| 容器 | 镜像 | 端口 | 说明 |
| --- | --- | --- | --- |
| WeKnora-frontend | wechatopenai/weknora-ui:v0.8.0 | 80 | Web UI（Nginx，反代 /api 到 app） |
| WeKnora-app | wechatopenai/weknora-app:v0.8.0 | 8080 | 后端 API（含 anydoc 进程内解析） |
| WeKnora-docreader | wechatopenai/weknora-docreader:v0.8.0 | 50051（内网） | 文档解析服务 |
| WeKnora-postgres | paradedb/paradedb:v0.22.6-pg17 | 5432（内网） | 主数据库 |
| WeKnora-redis | redis:7.0-alpine | 6379（内网） | 队列 / 缓存 |
| WeKnora-milvus | milvusdb/milvus:v2.6.11 | 19530 / 9091 | 向量库（compose profile `milvus`） |
| mineru-api | mineru:4（MinerU 4.0.4） | 127.0.0.1:18000 -> 8000 | MinerU V1 API 服务（GPU） |
| mineru-webui | mineru:4（MinerU 4.0.4） | 7860 | MinerU 自带 WebUI（GPU，可选） |

网络：WeKnora 服务位于 `weknora-main_WeKnora-network`，`mineru-api` 也接入该网络，容器内可用
`http://mineru-api:8000` 访问。

## 2. `.env` 关键配置

```ini
WEKNORA_VERSION=v0.8.0            # 固定版本，避免 latest 漂移

# ---- 向量库：Milvus ----
RETRIEVE_DRIVER=milvus            # 系统默认向量库（原 postgres）
MILVUS_ADDRESS=milvus:19530
MILVUS_COLLECTION=weknora_embeddings
MILVUS_METRIC_TYPE=IP             # IP / COSINE / L2，改后需重建 collection
COMPOSE_PROFILES=milvus           # 让 docker compose up -d 自动带上 Milvus 服务

# ---- SSRF 白名单 ----
# 必须包含 mineru-api，否则后端调用解析服务会被 SSRF 校验拦截
SSRF_WHITELIST_EXTRA=searxng,qdrant,milvus,weaviate,doris-fe,doris-be,minio,mineru-api
```

注意事项：

- `SSRF_WHITELIST_EXTRA` 会**覆盖** compose 内置默认值，自定义时必须把内置服务名一起写上。
- 知识库的向量库绑定创建后不可更改；切换向量库后，存量数据需新建知识库并重新导入/索引。
- 单机 Milvus 常驻约 1–2 GB 内存，请保证 Docker Desktop 内存分配充足。

## 3. 向量库：Milvus

```bash
# 启动（.env 已设 COMPOSE_PROFILES=milvus，可直接 up）
docker compose up -d --pull never

# 查看
docker ps --filter name=WeKnora-milvus
curl http://localhost:9091/healthz        # -> OK

# 回滚到 PostgreSQL 向量库
#   1) .env: RETRIEVE_DRIVER=postgres
#   2) docker compose up -d app --pull never
```

数据落在命名卷 `weknora-main_milvus_data`：`docker compose down` 不丢数据，`down -v` 会删除。

## 4. 文档解析：MinerU 4.0.4（V1 API）

### 4.1 启动 API 服务（GPU）

MinerU 4.0 起官方镜像提供 `mineru-kit api-server`，对外暴露 V1 接口。**必须加 `--gpus all`**，否则
standard/advanced 档会因取不到设备而失败（报 `Device string must not be empty`）：

```bash
docker run -d --name mineru-api --restart unless-stopped \
  --gpus all \
  --network weknora-main_WeKnora-network \
  -p 127.0.0.1:18000:8000 \
  -v mineru-api-data:/data \
  -e NVIDIA_VISIBLE_DEVICES=all -e NVIDIA_DRIVER_CAPABILITIES=compute,utility \
  mineru:4 mineru-kit api-server \
    --host 0.0.0.0 --port 8000 \
    --upload-dir /data/uploads --concurrency 2
```

可用参数：`--tier flash|basic|standard`（限制服务能力上限，默认不限制）、`--concurrency`、
`--preload-models`、`--api-key`、`--vlm-server-url`（外接 VLM）等。

### 4.2 解析档位与硬件要求

| 档位 | 说明 | 硬件 |
| --- | --- | --- |
| flash | 原生文本直出，最快 | CPU 即可 |
| basic | 小模型（OCR/公式/表格） | CPU 可用（较慢） |
| standard | 小模型 + VLM，默认阅读质量 | **需要 GPU/VLM** |
| advanced | 同模型、更多算力，难文档 | **需要 GPU/VLM** |

查看服务实际能力：`curl http://127.0.0.1:18000/v1/tiers`。

### 4.3 在 WeKnora 中配置

界面：**设置 → 解析引擎 → MinerU**，填写

- 自建端点：`http://mineru-api:8000`
- 解析档位：`standard`（CPU 环境请选 `flash` / `basic`）
- PDF 解析方式：`auto`

也可以直接写租户配置（服务端每次请求读取）：

```sql
update tenants
   set parser_engine_config = '{"mineru_endpoint":"http://mineru-api:8000",
                                "mineru_tier":"standard",
                                "mineru_parse_method":"auto"}'::jsonb
 where id = 10000;
```

### 4.4 接口适配说明（4.0 vs ≤ 3.x）

MinerU 4.0 **移除了** `/file_parse`、`/tasks`，改为 V1 流程：
`/v1/uploads` → 上传字节 → `/v1/uploads/{id}/complete` → `/v1/parse/jobs` → 轮询 → `/v1/files/{id}/content`
（ZIP 内含 `markdown.md` 与 `images/`）。

WeKnora 的适配方式：

- 自动探测 `GET /v1/health` 判定服务版本：4.0 走 V1 流程，≤ 3.x 继续走 `/file_parse`；
  可用 `mineru_api_version`（`auto` 默认 / `v1` / `legacy`）强制指定。
- 新增配置项：`mineru_tier`（档位）、`mineru_page_range`（如 `1-5,8,r3-r1` 或 `all`）；
  4.0 会忽略旧版的 Backend / vLLM 地址 / 公式表格开关（这些由服务端与档位决定）。
- `mineru_parse_method`（auto/ocr/txt）在 4.0 中映射为任务的 `ocr_mode`。

### 4.5 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `Device string must not be empty` | 容器未获得 GPU：启动时加 `--gpus all` |
| `mineru_endpoint failed SSRF validation` | `.env` 的 `SSRF_WHITELIST_EXTRA` 未包含 `mineru-api` |
| 档位报不支持 | 服务端用 `--tier` 限制了能力上限，去掉该参数重启 |
| 首次 standard 解析很慢 | 首次会加载 VLM 到显存；可加 `--preload-models` 预加载 |

## 5. 镜像构建与发布（Docker Hub 受限环境）

若所在网络无法直连 Docker Hub（`registry-1.docker.io` 解析异常/超时），需要：

1. 在 `~/.docker/daemon.json` 配置国内镜像加速，例如：
   ```json
   { "registry-mirrors": ["https://docker.1ms.run"] }
   ```
   改完重启 Docker Desktop（注意：非 library 仓库务必把可用镜像站排在首位）。
2. 拉取镜像时用 `docker.1ms.run/<repo>:<tag>` 显式前缀，或直接依赖 `registry-mirrors`。
3. **不要对本地构建的镜像执行 `docker compose pull`**（会被上游镜像覆盖）；拉起服务统一使用：
   ```bash
   docker compose up -d --pull never
   ```

### 5.1 重新编译后端（含 anydoc）

anydoc 是 Rust 静态库，需要 Rust 工具链（国内可用 rsproxy 镜像）：

```bash
# 1) 安装 Rust（容器内）
export RUSTUP_DIST_SERVER=https://rsproxy.cn RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
curl -sSf https://rsproxy.cn/rustup-init.sh | sh -s -- -y --profile minimal --default-toolchain stable

# 2) 编译 anydoc 静态库 -> third_party/anydoc-go/lib/linux_amd64_gnu/libanydoc_go.a
./scripts/build-anydoc-lib.sh

# 3) 编译后端（CGO + anydoc tag）
make build-prod GO_BUILD_TAGS=anydoc
```

> 不带 `GO_BUILD_TAGS=anydoc` 编译时，anydoc 走 stub 实现（引擎在界面上显示不可用，二进制中会出现
> `anydoc engine not built into this binary`），需要该能力时必须带 tag 编译。

产物注入镜像（镜像内 `/app/WeKnora` 即入口二进制）：

```bash
docker create --name app-build wechatopenai/weknora-app:v0.8.0
docker cp WeKnora app-build:/app/WeKnora
docker commit app-build wechatopenai/weknora-app:v0.8.0
docker rm app-build
docker compose up -d --force-recreate --pull never app
```

### 5.2 重新编译前端

```bash
cd frontend
npm ci --registry=https://registry.npmmirror.com
npm run build            # 产物在 frontend/dist

docker create --name ui-build wechatopenai/weknora-ui:v0.8.0
docker cp dist/. ui-build:/usr/share/nginx/html/
docker diff ui-build | grep index.html   # 确认 index.html 已更新（应输出 C .../index.html）
docker commit ui-build wechatopenai/weknora-ui:v0.8.0
docker rm ui-build
docker compose up -d --force-recreate --pull never frontend
```

## 6. 日常运维

```bash
# 状态 / 健康
docker compose ps

curl http://localhost/                   # 200

# 启停

nvidia-smi
docker exec mineru-api nvidia-smi
```
